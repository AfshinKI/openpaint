# Delivery plan: v2.1.0 requests

Status: first five slices implemented and locally validated; protected review pending

## Requested outcomes and order

1. Fix [issue #57](https://github.com/AfshinKI/openpaint/issues/57): copied Linux
   glass setup must work when the installed extension has no `hacks-level` key.
   See [the focused plan](0065-glass-schema-compatibility.md).
2. Enlarge top ribbon tool icons, retaining readable labels, keyboard focus,
   dropdown targets and minimum 1024×640 layout in both themes. Scope the change
   to ribbon controls rather than enlarging every menu/footer icon.
3. Replace the obsolete About text with current version/platform information,
   public developer credit, project website and a deliberate contact action.
   Approved details: Afshin Kashani, PhD, P.Eng, project website and GitHub Issues.
4. Expand Save As format discovery. PNG/JPEG/BMP/WebP export already exists;
   add monochrome 1-bit BMP as the first new encoding. Preserve .ora layer fidelity,
   original files and dirty-state/close guards. Require explicit flattening/lossy
   choices; cancelling or failing must never report the project saved.
5. Add top/left image-pixel rulers synchronized with zoom, pan and image bounds.
   Clarify smart guides: pointer indicators versus alignment/snapping while
   moving editable content. Define toggle/shortcut, snapping tolerance and bypass,
   clipping, fractional scale, undo and cancel before implementation.
6. Final integrated build, relevant native and tooling tests, formatting/QML lint,
   visual review at minimum size and fractional scales, then release preparation.

## Workflow and acceptance

Each implementation slice gets its own focused branch/PR from current origin/main;
merge through protection before dependent work. Documentation PR #58 is separate.
At the maintainer's request, application builds are deferred to the end. Earlier
slices remain unverified until required CI/final build evidence exists; this does
not waive protected checks. Independent slices may be prepared separately.

Keep 2.0.0 as the published version until a dedicated 2.1.0 release-preparation
change updates version, notes, website and fresh screenshots together. Do not
publish a release or claim features shipped merely because this plan exists.

## Current findings and open choices

The only open issue found on 2026-10-25 is #57. Its report contains private shell
context, which is not copied into fixtures/docs. Inspecting the official pinned
76 archive reproduced the missing root-schema key without installing anything.
The current About text still describes a Linux development drawing shell.
No implemented smart-guide/snapping system was found in the source search.
The maintainer approved existing export formats in Save As plus monochrome BMP,
and the proposed public About details. Recommended guide sequence: pixel rulers
and pointer markers first; then separately scoped optional canvas-edge/center
alignment snapping for selections/shapes/text, with a modifier bypass. Additional
unnamed formats are not in scope.

Next: complete the isolated schema compatibility fix and its mocked regression
checks; continue with independent ribbon/About work once their acceptance is set.
